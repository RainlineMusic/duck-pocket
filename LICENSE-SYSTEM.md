# Duck Pocket: офлайн-лицензия v1

## Поведение

Одна лицензия на пользователя ОС, общая для VST3/AAX/AU/CLAP и всех экземпляров.
При открытии без лицензии редактор показывает ввод ключа и OK. Звук проходит
без ducking и Output Gain, с сохранением объявленного lookahead. Загрузка
проекта не активирует плагин. Лицензия проверяется также без открытого редактора.
После активации в другом процессе/формате обновление занимает до двух секунд
при работающем message loop. При новом запуске ключ читается сразу.

Подписанный ключ хранится в userApplicationDataDirectory/RainlineMusic/DuckPocket/license.key
(macOS: ~/Library/Application Support; Windows: %APPDATA%). Это обычный файл:
скрытое расположение не является защитой. Защита — проверка подписи; изменение
флага в XML, настроек темы или текста файла не создаёт действительную подпись.
В аудиопотоке — только чтение атомарного bool, никаких диска, сети или RSA.
Проверка файла выполняется на message thread раз в 2 секунды и RSA только при
изменении содержимого. Активировать нужно отдельно для каждого пользователя ОС.

## Формат и математика

RSA-2048, показатель e=65537, подпись RSASSA-PKCS1-v1_5 с SHA-256.
Не использовать RSAKey::applyToValue как самодельную схему шифрования.
Открытый модуль n находится в Source/LicensePublicKey.h; секретный PEM только у владельца.

1. Сервер создаёт случайный UUID и сохраняет его за оплаченным заказом.
2. Строка M = ASCII("DuckPocket|1|" + UUID), без пробела/перевода строки.
   UUID — нижний регистр, 36 символов с дефисами.
3. H = SHA256(M), 32 байта.
4. T = hex(3031300d060960864801650304020105000420) || H (51 байт).
5. EM = 00 || 01 || FF (202 байта) || 00 || T (256 байт).
6. Подпись s = OS2IP(EM)^d mod n. Использовать OpenSSL/cryptography,
   не писать приватную RSA-математику вручную.
7. Ключ = "DP1." + UUID + "." + lowercase_hex(I2OSP(s,256)).
   Длина 553 символа. В письме — отдельная копируемая строка.
8. Плагин проверяет формат, 0 < s < n, затем s^65537 mod n == OS2IP(EM).
   Сравнивается вся ожидаемая структура, включая padding и DigestInfo.

Email/номер заказа не входят в ключ. Привязку UUID ↔ покупка хранит магазин.
Секрет нельзя встраивать в бинарник, JS страницы, репозиторий или CI-артефакты.
Файл DuckPocket-License-Owner-Kit.zip передан владельцу отдельно: PEM,
открытый ключ, ключ владельца для тестирования, генераторы Python/PHP.
Не терять PEM: новые ключи должны соответствовать уже опубликованному n.

## Генераторы

Python: `pip install cryptography`, затем
`python Tools/licensing/generate_license.py --private-key /private/signing.pem --license-id UUID`.
PHP: подключить Tools/licensing/generate_license.php и вызвать
`duckPocketLicense($privatePem, $uuid)`. Требуется PHP OpenSSL.
Это библиотечная функция, не открытый endpoint выдачи ключей.

## Связь с Lava

Интеграция оплаты в этот репозиторий НЕ входит. До генерации нужно проверить
подлинность события способом, предусмотренным актуальным API Lava, и подтвердить
статус успешной оплаты, товар, сумму и валюту через серверный API. Редирект браузера
«успешно» не является доказательством. Секрет Lava — только на сервере.

Транзакция БД + UNIQUE(provider, order_id): один UUID/ключ на один оплаченный заказ.
Повторные webhook, retry и повторная отправка письма используют тот же UUID.
Письмо отправляется после фиксации ключа в БД через очередь/outbox; сбой почты
не должен создавать новую лицензию. Не логировать PEM или целые ключи.

## Ограничения

Нет машинной привязки, срока действия, счётчика активаций или онлайн-отзыва.
Один ключ можно скопировать. Возврат денег не отзывает выданный офлайн-ключ.
Модифицированный бинарник может обойти проверку — это защита от простой
генерации/подмены ключа, не гарантия против взлома. Утечка PEM требует нового
набора ключей и версии плагина; добавление key-id для ротации — будущая версия.

## Проверки

Tests/license_test.cpp: стандартная тестовая RSA-подпись с другим открытым ключом,
подмена UUID/подписи, чужой ключ, некорректный ввод, dry без активации,
прослушивание post-filter, невозможность активации состоянием проекта.
Тестовые fixture не могут активировать производственный плагин.
Существующие DSP/null тесты остаются независимыми от лицензирования.
Интеграционные тесты используют friend-доступ из тестового executable;
в поставляемом плагине нет функции обхода/переменной окружения для активации.
